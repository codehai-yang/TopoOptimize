## 修复 GINE 推理切模型 best_modelV2.pt 启动失败

- 现象：`predict.py` 把 MODEL_PATH 改成 `best_modelV2.pt` 后，Java 报 `Python run fail` / `Python start fail`（GINEInferenceEngine.java:195/261），堆栈无有效信息。
- 根因：V2 checkpoint 的隐藏层维度是 128，而 `predict.py` 里 `HIDDEN_DIM=64` 写死，`load_state_dict` 直接 size mismatch，Python 在 main() 里加载模型时崩溃退出。
  - V1: input_proj.weight (64,200)、convs.0.nn.0.weight (128,64)
  - V2: input_proj.weight (128,200)、convs.0.nn.0.weight (256,128)
- 修复：`src/main/resources/scripts/predict.py`
  - `CostModelV2.__init__(hidden_dim, num_layers)` 参数化；
  - 新增 `_infer_arch(state_dict)` 从 input_proj.weight 形状和 `convs.N` 键推断 hidden/layers；
  - `get_model()` 兼容 `model_state_dict`/`state_dict` 包装格式；
  - `__main__` 加 try/except，把启动异常写入 `python_logs/startup_error.log`（原来 Java 把 stdout/stderr 重定向到 NUL，异常全被吞）。
- 验证：gine_env(F:\office\conda\envs\gine_env, py3.9 + torch2.8.0+cpu) 启动打印 `arch: hidden=128, layers=3`，socket 冒烟推理返回正常 JSON。
- 遗留：`normalization_params.json` 仍是 V1 时代（与 GINEModel/Pt 的 Jun-10 版本 md5 相同），若 V2 换了训练集需同步新的归一化参数，否则预测值会有系统偏差。
- 环境：跑推理用 `F:\office\conda\envs\gine_env\python.exe`；默认 PATH 上的 python 无 torch。

## 格式化 resources 下 93MB 单行 JSON

- 目标文件：`src/main/resources/测试新遗传算法2.json`（93,394,414 字节，单行压缩，顶层是 10 个方案对象）。
- 做法：写了流式美化器 `C:\Users\yang\AppData\Local\Temp\fmt_json.py`（按字符重排缩进，不整体 json.load，恒定内存，21 秒处理完 58.7M 字符）。
- 输出：`src/main/resources/测试新遗传算法2.pretty.json`，123,347,293 字节 / 2,886,545 行，indent=2，空容器保持 `{}` / `[]`。
- 校验：把输出重新压回单行后与原文件 md5 完全一致（ffc9a2c607bd596c4456b7c107abef1d），数据零改动。
- 注意：pom.xml 没有 `<resources>` 配置，resources 下所有文件都会随构建复制到 target/classes，这个 123MB 文件会拖慢每次 Build，长期建议移出 resources。

## 方案真实成本 vs 模型预测 误差对比脚本

- 新增 `eval_scheme_cost.py`（项目根目录）：流式读取优化结果 JSON 的每个方案 → 重建 GINE 输入特征 → 预测 → 输出 xlsx（`方案成本对比.xlsx`，含明细/误差汇总/口径说明 3 个 sheet + 柱状图）。
- 特征重建口径（对齐 `HarnessPackOpti.utils.Normalize#normalizeData`）：
  - 节点 = serviceableEdges 起终点名去重（189）；GNN 对节点排列等变，顺序无关。
  - x[:, :N] 回路单价矩阵：circuitInfo 每条回路按 起点位置→终点位置 累加 导线单价。
  - x[:, N] 湿区：回路湿区成本加成>0 时累加导线单价到起点。
  - edge_attr = [B/C/S one-hot, 分支长度]，长度取 length > referenceLength > C/S=200、B=0。
- 结论：模型当前对本 case **系统性低估约 40%**（真实 5552~5750，预测 3065~3529，MAPE 40.7%，秩相关 -0.22）。
- 原因：训练样本标签区间 2000~3030（均值 2205，5880 个样本，N=189/E=235），本 case 真实成本 2.2 倍于训练上限 → 模型外推饱和。
- 已验证模型+归一化本身没问题：拿 80 个已知训练样本跑同一套 normalize/predict，MAE 76.9 元（3.1%），无系统性偏差。
